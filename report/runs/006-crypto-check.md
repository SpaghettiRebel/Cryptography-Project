# Проверка криптографии: клиент

Способ проверки: отдельное чтение кода клиента и изменений `core/dh`, запуск быстрых тестов `client/internal/keyagree`, `client/internal/localdb`, `client/internal/ciphers`, `core/dh`, `core/kdf`. Сквозные тесты и детектор гонок при этой проверке не запускались, их результат взят из `006-test-full.txt`.

## Результаты

| Проверка | Результат | Доказательство |
|---|---|---|
| Длина и диапазон открытого значения собеседника | подтверждено | `keyagree` разбирает значение через `ParsePublic`: ровно 256 байт, 2 ≤ y ≤ p − 2; `SharedSecret` проверяет повторно |
| Принадлежность подгруппе простого порядка | исправлено | `ValidatePublic` требует y^q mod p = 1, q = (p − 1)/2; `TestValidatePublicSubgroup` |
| Параметры группы | подтверждено | RFC 3526, группа 14, g = 2, секрет из `crypto/rand` в диапазоне [2, p − 2] |
| Вывод сеансового ключа 128, 192, 256 бит | подтверждено | HKDF-SHA256, соль — номер чата, в info метка, алгоритм и длина; тест по вектору RFC 5869; длина ключа проверяется при записи |
| Ключ выводится для алгоритма чата, а не тестовой замены | подтверждено | ключи тестовой и сдаваемой сборок совпадают |
| Повторное подключение и повтор публикации | подтверждено | секрет записывается до публикации, повторно публикуется то же значение; сервер принимает повтор того же значения и отвергает только другое |
| Потеря секрета | подтверждено | значение опубликовано, а секрета и ключа нет — состояние `KEY_LOST` без публикации нового значения |
| Восстановление пары по секрету | подтверждено | `PrivateBytes` и `KeyPairFromPrivate`: ровно 256 байт, допустимы 2..p − 2, открытое значение пересчитывается; секрет не печатается |
| Что хранится на устройстве | соответствует требованиям | секрет до выработки ключа и сеансовый ключ в базе профиля; пароля и токена нет, токен только в памяти |
| Удаление секретов | исправлено | `secure_delete` и сброс журнала WAL после удаления; `TestDeletedSecretsLeaveNoBytes` ищет байты секрета и ключа в файлах базы и журнала |
| Секреты не уходят на сервер и в журналы | подтверждено | по сети идёт только открытое значение; ошибки хранилища и паники пишутся без значений |
| Запрещённые библиотеки | подтверждено | в клиенте только `crypto/tls`, `crypto/x509`, `crypto/sha256` (имя папки профиля), `crypto/rand` в тестах; `006-imports.txt` |
| Тестовый шифр не в сдаваемой сборке | подтверждено | подстановка только под тегом `devcipher`; в сдаваемой сборке MAGENTA и RC6 помечены недоступными |
| Фронтенд без криптографии | подтверждено | поиск по `client/frontend/src` и зависимостям, `006-imports.txt` |
| Пароль только по TLS, сертификат проверяется | подтверждено | TLS 1.3, доверенный сертификат только из выбранного файла, проверка имени сервера |

## Замечания

| Замечание | Серьёзность | Решение |
|---|---|---|
| Значения порядка 2q проходили проверку и раскрывали один бит секрета | средняя | исправлено, см. выше |
| Удалённые секреты могли оставаться в свободных страницах и журнале базы | средняя | исправлено; на Windows файл защищён только правами профиля пользователя, это описано в записке |
| Собранный на диске файл окна мог оказаться тестовой сборкой | средняя | в git он не попадает; после прогона на диске пересобрана сдаваемая сборка, в ней нет строк тестового шифра |
| Трассировка стека при панике пишется в журнал | низкая | оставлено: значения паники и аргументов-секретов в журнал не попадают |
| Базовый обмен Диффи–Хеллмана не защищён от подмены значений сервером | сведения | ограничение протокола, описано в записке |

## Что не проверено

- Настоящие MAGENTA и RC6: проверки идут на тестовом шифре.
- Права доступа к папке профиля на Windows.
- Стойкость к атакам по времени: возведение в степень не постоянного времени.
