# Проверка криптографии: клиент, сообщения и файлы

Способ проверки: отдельное чтение кода `client/internal/delivery`, `client/internal/localdb` (сообщения и миграция 002), `client/internal/service/messages.go`, обработчика картинок и фасада окна, а также `core/message` и `core/protocol`, на которых держится шифрование частей. Запуск быстрых тестов `client/internal/delivery`, `localdb`, `service` без тега и с `-short -tags devcipher`. Сквозные тесты и детектор гонок при этой проверке не запускались, их результат взят из `007-test-full.txt`, импорты — из `007-imports.txt` и повторного поиска по исходникам.

## Результаты

| Проверка | Результат | Доказательство |
|---|---|---|
| Шифрование и сборка только через `core/message` | подтверждено | `Seal` и `Assembler` вызываются из `delivery/sender.go` и `delivery/decryptor.go`; своей криптографии в клиенте нет; `007-imports.txt`: только пакет `delivery` импортирует `core/message` |
| Запрещённые библиотеки | подтверждено | в клиенте `crypto/rand`, `crypto/sha256`, `crypto/tls`, `crypto/x509`, `crypto/ecdsa` и `crypto/elliptic` (последние два только в тестах), `math/rand/v2` только в `delivery/faults_test.go`; `x/crypto`, `crypto/aes`, `crypto/cipher` нет |
| Тестовый шифр не в сдаваемой сборке | подтверждено | `ciphers.Resolve` подставляет тестовый шифр только под тегом; `delivery/TestReleaseBuild` без тега даёт ALGORITHM_UNAVAILABLE |
| В брокер и на сервер идёт только шифротекст | подтверждено в пределах тестового шифра | `core/message/TestOpenFieldsLeak`: открыты только идентификаторы чата и сообщения, номер, число частей, IV, длина; имя, тип, размер и данные лежат внутри шифротекста. `delivery/TestTextAllModes` и `TestFiles`: в шифротексте нет метки текста и имени. Сквозные `TestTextMessaging`, `TestFileMessaging`, `TestResilienceNoSecretsOnServer`: 228 и 11 строк поиска (метки, их hex, ключи в hex и base64), 202 значения секретов и ключей; в журналах сервера, дампе базы и файлах брокера совпадений 0 |
| Ключи не уходят в интерфейс | подтверждено | `MessageView` без ключа, IV, шифротекста и идентификатора сообщения; в `frontend/src` нет `dangerouslySetInnerHTML` и криптографии; состояние ключа доходит строкой |
| Где лежит ключ | соответствует требованиям | только `session_keys` в базе профиля; доставка берёт его через `Store.SessionKey`, в журналы и события он не попадает |
| IV на каждую часть, из `crypto/rand` | подтверждено | `core/message/seal.go`: 16 байт `rand.Reader` на каждую часть режимов с IV, у ECB IV нет; `TestTextAllModes` проверяет длину и попарное различие IV по всем 28 сочетаниям, включая служебные части |
| IV не переиспользуется при продолжении | подтверждено | после перезапуска уже записанные части шифруются заново, но выбрасываются, в спул пишется один шифротекст на номер; потерянный ответ даёт повторную отправку тех же байт, а не новое шифрование |
| Согласованность режимов и набивок | подтверждено | `modeOf` и `paddingOf` совпадают с порядком `core/modes` и `ciphers` (ECB, CBC, PCBC, CFB, OFB, CTR, RandomDelta; Zeros, ANSIX923, PKCS7, ISO10126); `Assembler` сверяет наличие IV с режимом; тесты на всех 28 сочетаниях: `delivery/TestTextAllModes`, `TestFiles`, `e2e/TestTextMessaging` |
| Граничные длины | подтверждено | `TestTextAllModes`: 1, 15, 16, 17, 49151, 49152, 49153 байт; `TestFiles`: 0, 1, 49153 байт; сквозные: 1 и 49153 |
| Ограничение Zeros | обойдено | `addFill` дописывает от 1 байта случайного заполнения до границы блока с ненулевым последним байтом, истинная длина данных стоит в заголовке; `TestTrailingZerosSurvive`, `TestTextAllModes`, файл `{0}` |
| Многопоточность | подтверждено | `Seal` шифрует части параллельно, `Assembler.Add` безопасен при одновременных вызовах, доставка запускает 4 горутины сборки; `TestParallelAssembly`, `TestSingleAndMultiThreaded`; детектор гонок для клиента и ядра без находок |
| Порядок частей, повторы | подтверждено | номер в открытом поле сверяется с номером внутри шифротекста; чужие чат и сообщение, несовпадение числа частей и размера отвергаются; повтор номера игнорируется; `TestOrderAndDuplicates`, `TestBadFragments`, `TestInnerBindingViolations` |
| Подмена и повреждение | подтверждено в границах | ошибка набивки, привязки или числа частей даёт `CORRUPTED` без паники (`TestTamperedCiphertext`, `TestParseInnerNoPanic`) |
| Потеря части | обнаруживается видимо | сообщение остаётся `RECEIVING` со счётчиком k из N, пока приходят остальные; пользователь может отменить |
| Подтверждение только после записи | подтверждено | `storeBatch`: сначала запись пачки в транзакции, потом `Ack`; `TestTextAllModes` считает записанные части на каждом подтверждении |
| После доставки у сервера ничего не остаётся | подтверждено со стороны клиента | подтверждение после записи; отправленная часть удаляется из спула; закрытие очереди сервером проверено в `integration` |
| Отмена и обрыв | подтверждено | `cancel_test.go`, `TestStreamEndings`, `TestSenderRestart`, `TestReceiverRestart`; частичные открытые куски удаляются при отмене, повреждении и перезапуске |
| Что лежит на диске | соответствует требованиям, см. замечания | открытые тексты и копии файлов (история), шифротекст в спулах приёма и отправки; пароля и токена нет; `secure_delete(ON)`; ключ в `session_keys` |
| Журналы | подтверждено | записи в журнал без значений: код ошибки, тип ошибки, стек паники без значений |
| Обработчик картинок | подтверждено | `/media/<seq>` отдаёт только готовые входящие картинки, тип по содержимому (PNG, JPEG, GIF, WebP, BMP; SVG нет), `nosniff`, `no-store`, остальное 404; `TestMediaHandler`, пробный запуск окна |
| Сохранение файла | подтверждено | путь из системного диалога, имя очищается `SafeFileName`, запись во временный файл рядом и переименование, размер сверяется с заявленным |

## Замечания

| Замечание | Серьёзность | Решение |
|---|---|---|
| Служебное сообщение отмены принималось любого размера: содержимое читалось целиком и сохранялось скрытой строкой, что обходило предел памяти | средняя | исправлено: отменой считается только содержимое ровно 16 байт, другое — обычный файл, для отмены читается не больше 16 байт; `delivery/TestClassify` (отмена 15, 17 байт и 1 МиБ) |
| Отмена в момент отправки первой части могла не поставить служебную отмену: признаком служило число подтверждённых частей | низкая | исправлено: отмена ставится и тогда, когда отправка части прервана с неизвестным исходом (обрыв, срок ответа, отмена во время вызова); `delivery/TestCancelAfterUncertainSend` |
| Нет аутентификации шифротекста: в CFB, OFB, CTR и Random Delta побитовое изменение меняет открытые данные, в ECB возможна подмена блоков; сервер может подставить свою часть раньше настоящей | сведения | ограничение задания, описано в записке и README |
| Удалённые куски открытых файлов (отмена, сбой, повреждение, перезапуск) могли оставаться в журнале WAL до его сброса | низкая | исправлено: после удаления кусков журнал переносится в основной файл и обрезается; `localdb/TestWipedChunksLeaveNoBytes` |
| Ошибка параметров чата при сборке считалась порчей сообщения, части удалялись | низкая | исправлено: сообщение остаётся `DECRYPT_PENDING` с кодом `INVALID_CHAT_PARAMS`, части целы, доступен повтор; `delivery/TestParamsErrorKeepsParts` |
| Полные проверки переписки идут на одном алгоритме; сквозной тест файлов — на трёх сочетаниях режима и набивки | низкая | исправлено частично: добавлен `delivery/TestTextMagentaSubstitute` — текст в чате MAGENTA (тестовая замена) в CBC/PKCS7 и CTR/Zeros; остальные проверки держатся на одном тестовом шифре до реализации MAGENTA и RC6 |
| Сбой записи в базу во время шифрования показывал уведомление каждые 2 с | низкая | исправлено: одно уведомление на сообщение, паузы 1, 2, 4, 5 с; `delivery/TestEncryptWriteFailureNotice` |
| `SafeFileName` не убирал символы управления направлением текста, имя вида `photo‮gpj.exe` выглядело как `photoexe.jpg` | низкая | исправлено: все символы категории Cf заменяются на `_`; `delivery/TestSafeFileName` |
| Сеансовый ключ после использования не обнуляется в памяти | сведения | оставлено: ключ и так хранится в базе профиля |
| Потерянная часть не обнаруживается по времени: сообщение остаётся в приёме, пока пользователь не отменит | сведения | оставлено, описано в записке |
| Базовый обмен Диффи–Хеллмана не защищён от подмены значений сервером | сведения | ограничение протокола, описано в записке; посредник может читать и подменять сообщения |

## Что не проверено

- Настоящие MAGENTA и RC6: все проверки идут на тестовом шифре.
- Сквозные тесты, детектор гонок и проверка импортов при этой проверке не запускались, взяты из `007-test-full.txt` и `007-imports.txt`.
- Права доступа к папке профиля и файлу базы на Windows.
- Отображение картинок и сохранение файлов в настоящем окне.
- Стойкость к атакам по времени при расшифровании и проверке набивки.
