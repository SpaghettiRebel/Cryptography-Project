# Проверка криптографии: доставка через брокер

Способ проверки: отдельное чтение кода и запуск тестов `core` и `server`, в том числе под детектором гонок для `core/message`, `core/protocol`, `internal/delivery`, `internal/rabbit`, `internal/rpc`. Тесты на настоящих Postgres и RabbitMQ и сквозные тесты при этой проверке не перезапускались: их результат взят из `005-test-full.txt`.

## Результаты

| Проверка | Результат | Доказательство |
|---|---|---|
| Сервер не импортирует криптоядро и шифры | подтверждено | `go list -deps -test ./...` в `server` без `cryptochat/core`; `005-imports.txt` |
| Тела сообщений непрозрачны | подтверждено | `delivery.Send` проверяет только длину; `rabbit` публикует тело без заголовков, `application/octet-stream`, persistent, mandatory; сверка тел в `integration/delivery_test.go` |
| Содержимого нет в журналах | подтверждено | журнал доставки пишет только постоянные сообщения, метод, код и длительность; поиск метки в журналах контейнеров, на диске брокера и в дампе Postgres |
| Метаданные не выходят за контракт | подтверждено | в конверте `chat_id` и `delivery_id`, в брокере имя очереди и тело. Отправитель, получатель, размер и время серверу видны |
| Размеры согласованы | подтверждено | заголовок 48 + IV 16 + `MaxCipherLen` 53 248 = `MaxWireSize` 53 312; 53 312 < 61 440; 61 440 + 24 < 65 536 |
| Наибольший фрагмент помещается при всех режимах | подтверждено на RC6-128 | `TestLargestFragmentFits`: 7 режимов × 4 набивки, не больше 50 576 байт. Размер шифротекста от шифра и длины ключа не зависит |
| Формат и версия не изменены | подтверждено | `Version = 1`, порядок полей и размер заголовка те же, изменены только пределы |
| Разбиение и сборка не теряют и не дублируют | подтверждено | тесты `core`; сквозной файл 3 МиБ, 64 фрагмента, совпал байт в байт |
| Хотя бы одна доставка, ack после приёма | подтверждено | `TestAckReachesBrokerOnlyFromClient`, `TestUnackedReturns`, `TestAckOfNotIssuedIgnored`; сквозной сценарий с обрывом |
| Очереди удаляются после закрытия и удаления контакта | подтверждено кодом и тестами | миграция 003, `RunCleanup`, `TestCleanupAfterClose`, `TestCleanupAfterRemoveContact`, `TestCleanupAfterRestart` |
| Гонки отправки и открытия с закрытием | подтверждено | `TestSendRaceCloseDuringEnsure`, `TestSendRaceCloseDuringPublish`, `TestSendRaceCloseAfterPublish`, `TestOpenRaceWithClose` |
| Postgres не хранит фрагменты | подтверждено | в `DeliveryStore` нет тела фрагмента; дамп базы проверен на метку |
| Посторонний не получает и не отправляет | подтверждено | `DeliveryState` с соединением по участникам; `TestStrangerSameAnswer`, `TestDeliveryRequiresSession` |
| Учётные данные брокера не утекают, порт не опубликован | подтверждено | ошибки соединения не пишутся в журнал; в `deploy/compose.yaml` нет `ports` у брокера |

## Замечания

| Замечание | Серьёзность | Решение |
|---|---|---|
| Открытие потока оставляло участника подключённым при сбое брокера | низкая при этой проверке, высокая при проверке проекта | исправлено, см. `005-design-review.md` |
| Очередь из гонки с закрытием при сбое удаления хранилась только в памяти и терялась при перезапуске | низкая | исправлено: `ReopenQueueCleanup`, `TestLateQueueSurvivesRestart` |
| Суммарный объём очередей не ограничен: предел действует на одну очередь | средняя, устойчивость, не утечка | оставлено, спецификация требует предел на очередь; описано в записке |
| Срока жизни у недоставленных фрагментов нет | низкая | оставлено: сохранность важнее, описано в записке |
| Клиент мог подтвердить номер, поставленный в начало очереди, до фактической записи в поток | сведения | оставлено: клиент вредит только себе |
| Пароль брокера открытым текстом в `rabbitmq.conf` с правами 0644, образ не закреплён по хешу | низкая | оставлено, как и у пароля базы; описано в записке |
| Версия формата не повышена при смене размера куска | сведения | оставлено: сохранённых сообщений нет; описано в записке |
| Файл больше примерно 60 МиБ для отсутствующего получателя упирается в `QUEUE_FULL` | сведения | оставлено, повтор отправки задача клиента; описано в записке |

## Что не проверено

- Настоящие MAGENTA и RC6: сквозная доставка идёт на тестовом шифре и одном сочетании CBC и PKCS7.
- Отсутствие метки подтверждает, что тело не передаётся открытым, но не стойкость настоящего шифра.
- Работа нескольких экземпляров сервера: сведения о запомненных очередях хранятся в памяти процесса, план предусматривает один экземпляр.
