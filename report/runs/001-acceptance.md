# Приёмка: 001-crypto-core

Фактический вывод — `001-test-full.txt` и `001-imports.txt`. Настоящие шифры относятся к документация фичи, поэтому всё ниже проверено на тестовом шифре.

## Критерии успеха

| Критерий | Статус | Чем подтверждено |
|---|---|---|
| SC-001 3 длины ключа × 7 режимов × 4 набивки × 5 длин | выполнено | `TestMatrix` |
| SC-002 режимы совпадают с определением | выполнено | `TestModesByDefinition`, `TestRandomDeltaExplicitByDefinition` |
| SC-003 1000 согласований, отказ на некорректных значениях | выполнено | `TestAgreement`, `TestValidatePublic` |
| SC-004 0 байт, 1 байт, размер фрагмента, 100 МБ при всех режимах | выполнено | `TestRoundTrip`, `TestRoundTripLarge` (100 000 000 байт) |
| SC-005 не менее 100 000 повреждённых фрагментов без паники | выполнено | `TestCorruptedInputs`; также fuzzing 30 с |
| SC-006 параллельная обработка идентична, нет гонок | выполнено | `TestParallel`, `-race` с `/c/msys64/ucrt64/bin` в начале PATH; прогон с `-short` |
| SC-007 ускорение не меньше 2 раз на 4 ядрах | выполнено | `TestParallelSpeedup`: 4.89 раза при 5 рабочих |
| SC-008 память не больше 16 фрагментов на 100 МБ | выполнено | `TestMemory`: пик счётчика 13 объёмов; рост кучи 11.9 МиБ. Куча замеряется с шумом среды выполнения |
| SC-009 отмена не дольше 1 с, монотонный прогресс | выполнено | `TestCancel`, `TestProgress` |
| SC-010 согласование не дольше 1 с на сторону | выполнено | `TestAgreement`: около 33 мс на полное согласование двух сторон в среднем |
| SC-011 нет утечек в открытых полях | выполнено | `TestOpenFieldsLeak`, `TestLengthHiddenWithinBlock`. Размер открыт с точностью до 1 МиБ по числу фрагментов, это описанное ограничение |
| SC-012 тестового шифра нет в сборке без тега, MAGENTA и RC6 дают ошибку | выполнено | `TestNoStubInReleaseBuild`, `TestUnavailable`. Сборку клиента проверит его фича |

| Требования | Статус | Чем подтверждено |
|---|---|---|

| FR-004 тестовый шифр не в сборке | выполнено | см. SC-012 |
| FR-005…FR-007 режимы, набивки, IV | выполнено | см. SC-001, SC-002, `TestDifferentIVDifferentCiphertext` |
| FR-008 единая ошибка набивки | выполнено | `TestBadCiphertext`, тесты `padding` |
| FR-009 параллельность | выполнено | `TestModes_ParallelMatchesSequential`, `TestParallel` |
| FR-010…FR-013 Диффи-Хеллман и вывод ключа | выполнено | группа 14 пересчитана по формуле RFC 3526 и сверена с текстом RFC; вектор A.1 RFC 5869 сверен с текстом RFC; `TestAgreementToSessionKey` |
| FR-014…FR-018 формат и сборка | выполнено | тесты `protocol` и `message` |
| FR-019, FR-020 поток, отмена, прогресс | выполнено | см. SC-008, SC-009. `Assembler.Add` держит память на вызов, а число вызовов ограничивает вызывающий код, это записано в контракте |

| FR-022 секреты не в ошибках | выполнено | `TestErrorsHaveNoSecrets`, `TestSecretNotPrinted` |
| FR-023 нет готовых шифров и обмена ключами | выполнено | `001-imports.txt` |
| FR-024 ограничения и источники для записки | выполнено | `report/note.md`, исследование решений, R9 |

## Отличия реализации от плана

- Окно параллельности 5 вместо 8: на фрагмент в пике приходятся три объёма, поэтому 8 нарушали бы SC-008.
- `TestNoStubInReleaseBuild` проверяет зависимости других пакетов: шаблон `cryptochat/core/...` включает сам `stubcipher`, поэтому поиск по общему списку всегда срабатывал бы.
- Сверх плана после ревью: проверка длины результата шифра и права `0600` на файлы.
