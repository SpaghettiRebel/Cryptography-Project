# Ревью архитектуры: 001-crypto-core

Запрещённых импортов, `math/rand` и `big.Int.Exp` с модулем нет; `protocol` зависит только от стандартной библиотеки; тестовый шифр не входит в зависимости других пакетов без тега.

## Исправлено

| Замечание | Решение |
|---|---|
| Длина шифротекста давала ошибку с подробностями (`modes_impl.go`) | Ровно `padding.ErrBadPadding` |
| Контракт требовал `ErrBadPadding` и для ошибок программиста в `Unpad` | Контракт уточнён |
| «Точный повтор» в контракте при фактическом игнорировании номера | Контракт и модель данных уточнены |
| Память `Assembler.Add` ограничивает вызывающий код, но это не записано | Записано в контракте и комментарии |
| `progress(0, 0)` для пустого сообщения не описан | Записано |
| Колбэк `Progress` под блокировкой и паника в колбэке или `emit` | Записано: это ошибка вызывающего кода |
| Параметр `cipher` затенял пакет | Переименован |
| Результат шифра неверной длины портил соседний блок | `checkedCipher`, тест `TestWrongResultLength`; важно для `002-ciphers` |
| Проба длины не учитывала `Read` с `(0, nil)` | `io.ReadFull`, тест `TestSealZeroLengthReads` |
| Расшифрованный файл создавался с правами `0644` | `0600` |
| Схема зависимостей в `plan.md` не совпадала с кодом | Исправлена |
| Константа размера секрета объявлена в `dh` и `kdf` | Оставлена, чтобы не связывать пакеты; согласованность проверяет `TestAgreementToSessionKey` |

## Принято без изменений

- `TestNoStubInReleaseBuild` и `TestNoCipherDependency` пропускаются под `-short`, потому что запускают `go list`; они идут в полном `go test`. Проверку сборки клиента добавит его фича.
- `EncryptFile` читает файл целиком: метод перенесён из `lab3` и работает как есть, клиент обрабатывает большие файлы через `message`. В комментарий добавлено предупреждение.
- Паника при nil-аргументах `dh.ModPow` и нулевых значениях структур: это нарушение инварианта программиста, конституция это допускает.
- В перенесённых пакетах сообщения об ошибках на английском и нет комментариев к части экспортов, как в `lab1` и `lab3`. Не менялось, чтобы перенос оставался сравнимым с исходником.
- Лишние экспорты `core` не важны для сервера, потому что он использует только `protocol`.

## Что придётся защищать устно

Вывод ключа HKDF-SHA256 и его контекст; группа 14 и отсутствие защиты от подмены; независимые фрагменты и `Fill`; почему открыты номер и общее число фрагментов; Random Delta; тестовый шифр и тег; собственный формат вместо Protobuf в `core`; оракул набивки и отсутствие аутентификации.
