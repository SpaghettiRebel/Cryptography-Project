# Вариант заданий на оценку «отлично» к курсовому проекту по основам криптографии (2026–2027 уч. г.)

Источник: `docs/task.pdf` (6 страниц). Текст ниже — структурированная расшифровка оригинала;
формулировки сохранены, добавлена только нумерация подпунктов (3.1, 3.2, …) для удобства ссылок
из spec/tasks. Блоки-цитаты — пояснения, а не текст задания.

## Общие ограничения

- **Разработка на Python не допускается.**

## Задание 1. Симметричные алгоритмы

Реализовать **два симметричных алгоритма шифрования**, реализующих **интерфейс симметричного
алгоритма шифрования** (использование сторонних реализаций алгоритмов не допускается).

Варианты алгоритмов указаны в приложении 1; выбранная пара алгоритмов должна быть **уникальна
в рамках студенческой группы** (независимо от выбранного варианта заданий).

## Задание 2. Протокол Диффи-Хеллмана

Реализовать **протокол Диффи-Хеллмана** (использование сторонних реализаций протокола
не допускается).

## Задание 3. Серверное приложение

Реализовать **консольное серверное приложение**, взаимодействие с которым возможно при помощи
сетевого протокола и надстроек над ним (REST API, gRPC, WCF, etc.), API которого предусматривает
возможность выполнения следующих протоколов (протокол может быть организован посредством
выполнения нескольких связанных запросов):

- **3.1.** Регистрация пользователя по паре логин + пароль (хранение пароля в открытом виде
  запрещено (используйте механизм хеширования); логины пользователей уникальны);
- **3.2.** Авторизация пользователя по паре логин + пароль;
- **3.3.** Управление контактами пользователя (запрос на добавление контакта,
  принятие/отклонение запроса на добавление контакта, удаление существующего контакта);
- **3.4.** Создание «комнаты» для организации защищённого обмена сообщениями между авторизованным
  пользователем и его контактом (секретный чат) с возможностью выбора используемого алгоритма
  шифрования из реализованных в п. 1;
- **3.5.** Закрытие ранее созданного секретного чата;
- **3.6.** Подключение и отключение клиентов от секретного чата;
- **3.7.** Организация распределения сеансового ключа симметричного алгоритма, сгенерированного
  посредством протокола Диффи-Хеллмана;
- **3.8.** Обработка пользовательских запросов на приём и передачу данных между клиентами,
  участвующими в защищённом обмене сообщениями.

Требования к взаимодействию:

- **3.9.** Взаимодействие с сервером должно быть реализовано **в асинхронном стиле с использованием
  брокера сообщений** (Redpanda, Apache Kafka, Apache ActiveMQ Artemis, RabbitMQ, MSMQ и т. д.),
  предоставляющего очередь сообщений, **producer и consumer которой находятся на стороне
  серверного приложения**.
- **3.10.** Сообщениями, поступающими в брокер, должны являться **фрагменты шифротекста**.
- **3.11.** После передачи зашифрованного фрагмента сообщения клиенту-потребителю **запрещено
  дальнейшее _контролируемое_ хранение этого фрагмента**.
- **3.12.** Формат сериализации сообщений продумайте самостоятельно.

Опционально:

- **3.13.** Реализовать этап развёртывания серверного приложения на основе абстракции инверсии
  управления (IoC), реализованной в виде механизма внедрения зависимостей (DI). Конфигурирование
  этапа развёртывания обеспечьте при помощи конфигурационных файлов и их трансформаций.
- **3.14.** Обеспечить возможность репликации хранящихся в брокере сообщений данных.

> Замечание по 3.1: запрет на сторонние реализации в заданиях 1 и 2 относится к симметричным
> алгоритмам и протоколу Диффи-Хеллмана. Принятое решение: хеширование реализовывать самостоятельно
> не нужно, если задание прямо не требует обратного.

## Задание 4. Клиентское приложение

Реализовать **приложение (оконное или web)**, позволяющее:

- **4.1.** Инициировать выполнение протокола регистрации нового пользователя;
- **4.2.** Инициировать выполнение протокола авторизации зарегистрированного пользователя;
- **4.3.** Инициировать выполнение протокола управления контактами пользователя (добавление нового
  контакта, подтверждение/отклонение нового контакта, удаление существующего контакта);
- **4.4.** Инициировать выполнение протокола на создание секретного чата с указанием используемого
  симметричного алгоритма шифрования, режима шифрования, режима набивки;
- **4.5.** Инициировать выполнение протокола на подключение к ранее созданному секретному чату;
- **4.6.** Инициировать выполнение протокола на отключение от секретного чата, к которому в данный
  момент существует подключение;
- **4.7.** Генерировать вектор инициализации (IV) для его применения в режимах шифрования: CBC,
  PCBC, CFB, OFB, CTR, Random Delta;
- **4.8.** Организовать функционал для выбора данных, подвергаемых шифрованию и передаче второй
  стороне, участвующей в секретном чате:
  - **4.8.1.** ввод текста в текстовое поле;
  - **4.8.2.** выбор файла с данными при помощи стандартного диалога выбора файла;
- **4.9.** Многопоточно (по возможности) шифровать данные сеансовым ключом симметричного алгоритма
  (с использованием одного из режимов шифрования: ECB, CBC, PCBC, CFB, OFB, CTR, Random Delta;
  также с использованием режима набивки: Zeros, ANSI X.923, PKCS7, ISO 10126);
- **4.10.** Инициировать выполнение протокола передачи вычисленного шифротекста на сторону серверного
  приложения при помощи нажатия кнопки на UI;
- **4.11.** Инициировать выполнение протокола получения шифротекста со стороны серверного приложения
  в фоновом режиме;
- **4.12.** Многопоточно (по возможности) дешифровать полученный шифротекст распределённым между
  сторонами сеансовым ключом симметричного алгоритма (с учётом режима шифрования и режима набивки,
  применённых при операции шифрования);
- **4.13.** Отображать список активных секретных чатов текущего пользователя;
- **4.14.** Отображать переданные и полученные сообщения в надлежащем виде (текст как текст, картинки
  как картинки, остальные файлы — как компоненты UI, позволяющие сохранить файлы на локальное
  устройство при помощи стандартного диалога сохранения файла);
- **4.15.** Сохранять переданные и полученные сообщения в локальной СУБД, устройство и взаимодействие
  с которой определите самостоятельно;
- **4.16.** Отображать прогресс операций шифрования / дешифрования / передачи данных / получения
  данных при помощи элементов управления типа ProgressBar;
- **4.17.** Инициировать отмену операции шифрования / дешифрования / передачи данных / получения
  данных по запросу пользователя;
- **4.18.** Инициировать выполнение протокола на отключение одного или обоих клиентов от секретного
  чата.

Общие требования к приложению:

- **4.19.** Приложение должно иметь интуитивно понятный и удобный пользовательский интерфейс.
- **4.20.** Поведение клиентского приложения, приводящее к аварийной ситуации, не допускается.

## Пояснительная записка

Для получения положительной (3 и выше) оценки за курсовой проект необходимо подготовить и сдать
на кафедру **распечатанную пояснительную записку**. В пояснительной записке необходимо:

- описать реализованные алгоритмы шифрования и протоколы с теоретической точки зрения;
- описать архитектуру своего комплекса приложений;
- описать использованные средства использованных языков программирования и применённых при
  разработке технологий.

### Структура

1. Титульный лист
2. Содержание
3. Введение
4. Теоретическая часть (описание алгоритмов шифрования и протоколов)
5. Практическая часть (описание архитектуры комплекса приложений, использованных языков
   программирования и применённых при разработке технологий)
6. Вывод
7. Список использованных источников
8. Приложение (ссылка на репозиторий с исходным кодом)

### Оформление

| элемент | требования |
|---|---|
| Поля | левое 20 мм, остальные 15 мм |
| Нумерация страниц | начиная с титульного листа, индексация инкрементальная начиная с 1; на титульном листе номер страницы не указывается |
| Заголовки и подзаголовки разделов | Times New Roman 16pt, междустрочный интервал 1.5pt, выравнивание по левому краю |
| Основной текст | Times New Roman 14pt, междустрочный интервал 1.15pt, выравнивание по ширине; абзацные отступы |
| Рисунки | выравнивание по центру |
| Таблицы | выравнивание по центру |
| Листинги | Consolas 12pt, междустрочный интервал 1pt, выравнивание по левому краю |
| Список использованных источников | оформление по ГОСТ 7.0.100-2018 |

Подписи (# — номер при сквозной нумерации по всей пояснительной записке, индексация инкрементальная
начиная с 1; объект и подпись к нему должны находиться на одной странице):

| подпись | формат | где | оформление |
|---|---|---|---|
| к рисунку | `Рисунок #. <Описание рисунка>` | под рисунком | Times New Roman 12pt, курсивный, междустрочный интервал 1pt, по центру |
| к таблице | `Таблица #. <Описание таблицы>` | над таблицей | Times New Roman 12pt, курсивный, междустрочный интервал 1pt, по левому краю |
| к листингу | `Листинг #. <Описание листинга>` | над листингом | Times New Roman 12pt, курсивный, междустрочный интервал 1pt, по левому краю |
