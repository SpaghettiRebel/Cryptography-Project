# Контракт: запуск и тестовый клиент

## Запуск

Требуется запущенный Docker Desktop. Команда выполняется из папки `project`:

```text
docker compose -f deploy/compose.yaml up --build
```

| контейнер | назначение |
|---|---|
| `init` | один раз создаёт секреты и сертификат в томе `secrets`, копирует открытый сертификат в `deploy/certs/server.crt`, завершается |
| `postgres` | Postgres 16; пароль из `POSTGRES_PASSWORD_FILE`; данные в томе `pgdata`; порт наружу не открыт |
| `server` | запускается после `init` и готовности базы; порт `8443` наружу; пользователь без прав root |

Готовность сервера: `docker compose ps` показывает `healthy`. Удаление всех данных и секретов:

```text
docker compose -f deploy/compose.yaml down -v
```

## Подкоманды сервера

| команда | назначение | код завершения |
|---|---|---|
| `server` | запуск | 0 при штатной остановке; 1 при ошибке запуска |
| `server init` | создаёт отсутствующие секреты, существующие не меняет; открытый сертификат копирует всегда | 0 или 1 |
| `server healthcheck` | запрос к gRPC Health по TLS | 0 при `SERVING`, иначе 1 |

## Параметры сервера

Только переменные окружения, секреты — через файлы:

| переменная | по умолчанию | смысл |
|---|---|---|
| `CHAT_LISTEN` | `:8443` | адрес |
| `CHAT_DB_HOST`, `CHAT_DB_NAME`, `CHAT_DB_USER` | `postgres`, `cryptochat`, `cryptochat` | база |
| `CHAT_DB_PASSWORD_FILE` | `/secrets/db_password` | файл пароля |
| `CHAT_TLS_CERT`, `CHAT_TLS_KEY` | `/secrets/server.crt`, `/secrets/server.key` | сертификат и ключ |
| `CHAT_LOG_LEVEL` | `info` | уровень журнала |
| `CHAT_SECRETS_DIR`, `CHAT_CERTS_OUT`, `CHAT_SECRETS_OWNER` | `/secrets`, `/certs`, `65532` | только для `server init`: куда записать секреты и копию сертификата, владелец ключа |
| `CHAT_HEALTH_ADDR` | `localhost:8443` | только для `server healthcheck`: адрес проверки |

Переменные самого Compose: `CHAT_PUBLIC_PORT` (порт на хосте, `8443`) и `CHAT_CERTS_DIR` (папка копии сертификата на хосте, `./certs` рядом с `compose.yaml`).

Неверная конфигурация и отсутствующие файлы — ошибка запуска с понятным сообщением, без значений секретов.

Тома `secrets` и `pgdata` удаляются только вместе (`down -v`): новый `db_password` не подойдёт к уже созданной базе, и сервер завершится с ошибкой через 60 с ожидания.

## Тестовый клиент `chatcli`

```text
go run ./server/cmd/chatcli [-addr localhost:8443] [-ca deploy/certs/server.crt] [-session <файл>] <команда>
```

| команда | действие |
|---|---|
| `register <логин>` | регистрация; пароль читается из stdin |
| `login <логин>` | вход; пароль из stdin; сессия сохраняется в файл с правами `0600` |
| `logout` | завершение сессии и удаление файла |
| `contact-request <логин>` | запрос на контакт |
| `contact-accept <логин>`, `contact-reject <логин>` | ответ на входящий запрос |
| `contact-remove <логин>` | удаление контакта |
| `contacts` | контакты, входящие и исходящие запросы |

Код завершения 0 при успехе. При ошибке печатается причина из `ErrorInfo` и код завершения 1. Клиент доверяет только указанному файлу сертификата. Пароль не передаётся аргументом, чтобы не попадать в историю команд и список процессов; один завершающий перевод строки из stdin обрезается.
