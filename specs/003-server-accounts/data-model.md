# Data Model: Основа сервера

Идентификаторы пользователей — `uuid`, создаются базой. Время — `timestamptz`.

## users

| поле | тип | правило |
|---|---|---|
| `id` | uuid | первичный ключ |
| `login` | text | как при регистрации: 3–32 символа `[A-Za-z0-9_.-]` |
| `login_norm` | text | нижний регистр; **уникальный индекс** |
| `password_hash` | text | PHC-строка argon2id с параметрами и солью |
| `created_at` | timestamptz | |

Пароль: от 8 до 128 байт; проверяется до вычисления хеша.

## sessions

| поле | тип | правило |
|---|---|---|
| `token_hash` | bytea | SHA-256 от сессии, первичный ключ, 32 байта |
| `user_id` | uuid | внешний ключ, `ON DELETE CASCADE`, индекс |
| `expires_at` | timestamptz | создание + 24 часа |

Состояния: действует → просрочена или завершена. Выход удаляет строку; повторный выход с той же сессией даёт ошибку авторизации. Просроченная отвергается всегда, а удаляется при следующем входе пользователя.

## contact_requests

| поле | тип | правило |
|---|---|---|
| `sender_id`, `recipient_id` | uuid | внешние ключи; `sender_id <> recipient_id`; **первичный ключ на паре** |
| `created_at` | timestamptz | |

Запрос существует только пока не обработан: принятие, отклонение и встречный запрос его удаляют.

## contacts

| поле | тип | правило |
|---|---|---|
| `user_low`, `user_high` | uuid | `user_low < user_high`, внешние ключи, **первичный ключ на паре** |
| `created_at` | timestamptz | |

## Переходы для пары A и B

```text
нет связи ──A: запрос──► запрос A→B ──B: принять──► контакт ──любой: удалить──► нет связи
                             │  └─B: отклонить──► нет связи
                             └──B: встречный запрос──► контакт
```

- Запрос в состоянии «запрос A→B» от A: `DUPLICATE_REQUEST`.
- Запрос в состоянии «контакт»: `ALREADY_CONTACT`.
- Запрос себе: `SELF_REQUEST`; несуществующий логин: `USER_NOT_FOUND`.
- Принятие и отклонение несуществующего запроса: `REQUEST_NOT_FOUND`. Принимать может только получатель, поэтому посторонний получает ту же ошибку, а данные не меняются.
- Удаление несуществующего контакта: `CONTACT_NOT_FOUND`.

Каждая операция — одна транзакция с блокировкой обеих строк `users` по возрастанию `id`.

## schema_migrations

`version int` — первичный ключ. Миграции применяются при запуске под блокировкой `pg_advisory_lock`, поэтому параллельный запуск безопасен.

## Интерфейс хранилища

Сервисы работают с интерфейсами `AccountStore` и `ContactStore`; их реализуют `postgres` и `memstore`. Ошибки — сентинелы пакета `store`, в том числе `ErrUnavailable`.
