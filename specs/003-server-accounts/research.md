# Research: Основа сервера

Отмеченное как «проверено» запущено на этой машине. **Docker на момент планирования не был запущен, поэтому Compose и образы ещё не проверялись.**

## R1. Версии зависимостей

**Decision**: `grpc v1.67.3`, `protobuf v1.34.2`, `pgx v5.7.2`, `x/crypto v0.31.0`, зафиксировать в `go.mod`.

**Rationale**: последние версии этих библиотек требуют Go новее, а проект на 1.22. **Проверено**: с `GOTOOLCHAIN=local` и `go 1.22` модуль с этими версиями собирается, `go.mod` остаётся на 1.22.

**Alternatives**: поднять Go до новой версии. Отклонено: конституция задаёт 1.22+, а для целей задания новые версии не нужны.

## R2. Генерация gRPC-кода

**Decision**: `.proto` хранится в `proto/`, код генерируется командой `buf generate` из контейнера `bufbuild/buf` с закреплённым тегом и удалёнными плагинами `buf.build/protocolbuffers/go:v1.34.2` и `buf.build/grpc/go:v1.5.1`: локальных плагинов в этом образе нет. Запасной вариант без внешнего реестра плагинов: контейнер `golang:1.23-alpine` с `protoc`, `protoc-gen-go@v1.34.2` и `protoc-gen-go-grpc@v1.5.1`. Сгенерированный код лежит в репозитории.

**Rationale**: `protoc` и `buf` на машине не установлены (проверено), а Docker всё равно нужен. Сборка и тесты не зависят от генератора.

**Alternatives**: установка `protoc` на машину; ручная запись сообщений без Protobuf. Второе противоречит конституции.

## R3. Параметры argon2id

**Decision**: `t = 3`, `m = 64 МиБ`, `p = 4`, соль 16 байт, результат 32 байта — второй рекомендованный набор RFC 9106. Хеш хранится в PHC-строке с параметрами. Одновременных вычислений не больше 4 (семафор), поэтому память хеширования ограничена 256 МиБ.

**Проверено прототипом**: один хеш около 58 мс, 8 одновременно около 518 мс при цели в 1 с. Значения в контейнере нужно перемерить.

**Перемерено в контейнере** (T032, `golang:1.23-alpine`, Docker Desktop): один хеш 129 мс, 8 одновременно 494 мс; вход через сервер в Compose 153 мс при цели в 1 с. Параметры не меняются.

**Alternatives**: минимум OWASP `t = 2, m = 19 МиБ` быстрее, но запас по времени и так большой.

**Равное время**: для несуществующего логина проверка идёт по заранее вычисленному при запуске фиктивному хешу с теми же параметрами (FR-004, SC-010).

## R4. Сессии

**Decision**: 32 байта из `crypto/rand`, передаются в base64url в метаданных `authorization: Bearer …`. В базе хранится SHA-256 от значения. Срок 24 часа. При каждом входе просроченные сессии пользователя удаляются.

**Rationale**: у случайного значения 256 бит энтропии, поэтому медленный хеш не нужен, а быстрый оставляет проверку лёгкой. Похищенная база не даёт рабочих сессий.

**Alternatives**: JWT без хранения. Отклонено: нужен отзыв при выходе.

## R5. Согласованность контактов

**Decision**: каждая операция над парой — одна транзакция Postgres, которая сначала блокирует обе строки `users` через `SELECT … FOR UPDATE` в порядке возрастания идентификатора. Контакт хранится упорядоченной парой (`user_low < user_high`) с первичным ключом.

**Rationale**: упорядоченная блокировка исключает взаимную блокировку и делает встречные запросы, принятие и удаление последовательными (FR-012, FR-014). Ограничения базы — вторая линия защиты. Уникальность логина обеспечивает индекс по `login_norm`: ошибку `23505` код превращает в `LOGIN_TAKEN`.

**Alternatives**: уровень Serializable с повторами сложнее и не нужен при таких коротких транзакциях.

## R6. TLS и секреты развёртывания

**Decision**: контейнер `init` запускает `server init` и создаёт в именованном томе, если их ещё нет:

- случайный пароль базы;
- самоподписанный сертификат ECDSA P-256 на 1 год с именами `localhost`, `server`, `127.0.0.1`, и его ключ.

Открытый сертификат всегда копируется в `deploy/certs/server.crt` для клиента, поэтому после `down -v` клиент не останется со старым файлом. Права: `server.key` — `0600`; `db_password` — `0644`, потому что его читают и сервер, и Postgres (uid 70 в образе Alpine, значение подтверждается запуском). Том подключён только к этим контейнерам. Минимальная версия TLS — 1.3. Postgres читает пароль через `POSTGRES_PASSWORD_FILE`.

**Rationale**: одна команда, никаких секретов в репозитории (FR-016). Самогенерация в томе повторяема; `docker compose down -v` создаёт всё заново. Принцип I разрешает TLS канала.

**Alternatives**: заранее созданные файлы в репозитории нарушают FR-016; `.env` требует ручного шага. `InsecureSkipVerify` в клиенте отклонён: тестовый клиент явно доверяет файлу сертификата.

## R7. Ошибки API

**Decision**: коды gRPC и `errdetails.ErrorInfo` с полем `reason` (`LOGIN_TAKEN`, `INVALID_LOGIN`, `INVALID_PASSWORD`, `INVALID_CREDENTIALS`, `UNAUTHENTICATED`, `USER_NOT_FOUND`, `SELF_REQUEST`, `ALREADY_CONTACT`, `DUPLICATE_REQUEST`, `REQUEST_NOT_FOUND`, `CONTACT_NOT_FOUND`, `STORE_UNAVAILABLE`).

**Rationale**: одних кодов не хватит, чтобы различить ошибки из FR-011. Клиенту нужен машинно-читаемый признак.

## R8. Устойчивость и ограничения

**Decision**:

- `pgxpool` с таймаутом запроса 3 с и повторным подключением; при сбое код `Unavailable`, причина `STORE_UNAVAILABLE`;
- `MaxRecvMsgSize` 64 КиБ (фича доставки поднимет лимит для своих потоков);
- перехватчик ловит панику обработчика, журналирует её и возвращает `Internal`, так что сервер не падает;
- стандартный gRPC Health сообщает `SERVING` только при успешном запросе к базе (проверка раз в 2 с); контейнер проверяется подкомандой `server healthcheck`;
- по сигналу `GracefulStop` с пределом 10 с, затем `Stop`;
- журнал `slog`: метод, код, длительность, без тел запросов и метаданных.

## R9. Тестирование

**Decision**:

| уровень | чем | что |
|---|---|---|
| сервисы | `memstore` | правила логина, входа, сессий и контактов, быстро, без Docker |
| хранилище | Postgres через `CHAT_TEST_POSTGRES_DSN` | одновременность (SC-001, SC-004), миграции, ограничения; без переменной тест явно пропускается |
| gRPC | `bufconn` с TLS и `memstore` | авторизация, ошибки, лимиты, паника, журналы |
| сквозной | тег `e2e`, настоящий Compose | SC-002, SC-005…SC-008 |

Тестовый клиент `chatcli` — обычная консольная программа: `register`, `login`, `logout`, `contact-request`, `contact-accept`, `contact-reject`, `contact-remove`, `contacts`. Сессию сохраняет в файл с правами `0600`.

## R10. Ограничения для пояснительной записки

- нет ограничения числа попыток входа;
- запрос на контакт раскрывает существование логина;
- самоподписанный сертификат: клиент доверяет файлу, а не центру сертификации;
- пароль передаётся серверу внутри TLS, а не защищается на клиенте;
- секреты развёртывания лежат в томе в открытом виде: для учебной работы этого достаточно, но это не хранилище секретов;
- сессия не привязана к устройству, а её срок не продлевается;
- сервер подключается к базе без TLS: порт базы не опубликован, трафик идёт только внутри сети Compose;
- `db_password` имеет права `0644`: файл читают сервер и Postgres под разными пользователями, том подключён только к ним;
- сертификат действует год и сам не обновляется, для замены нужно пересоздать том `secrets`;
- порт сервера открыт на всех интерфейсах хоста, чтобы клиент мог подключиться с другой машины;
- просроченные сессии удаляются только при следующем входе того же пользователя.
